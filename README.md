# botik_sonya

Telegram-бот для личного квеста и локальный визуальный конструктор ROADMAP.

Первая тестовая версия уже умеет:

- один раз активироваться в чате участницы через `/start` и после этого писать ей по таймеру;
- запускать квест командой администратора `/start_quest` с задержкой из `.env`;
- сохранять таймер в SQLite, чтобы перезапуск процесса не отменял ожидающее интро;
- записывать реальные пересланные сообщения в «воспоминания» и повторно пересылать их для проверки `Forwarded from`;
- исполнять JSON-ROADMAP с текстом, фото, видео, аудио, документами, паузами, вопросами, подсказками, кнопками, переходами и реконструкциями воспоминаний;
- работать через HTTP/SOCKS-прокси из `.env`;
- отдельно проверять прокси отправкой тестового сообщения;
- визуально собирать ROADMAP в локальном браузерном конструкторе.

> Репозиторий публичный. Никогда не коммить `.env`, токен бота, SQLite-базу и приватные медиа. Они уже исключены через `.gitignore`.

## 1. Установка

Нужен Python 3.12+.

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
```

Заполни минимум:

```dotenv
BOT_TOKEN=...
ADMIN_TELEGRAM_ID=...
PROXY_URL=socks5://user:password@host:port
```

`SONYA_TELEGRAM_ID` можно оставить пустым. Тогда бот привяжет как участницу первого не-администратора, который отправит `/start`, и сохранит её `chat_id` в `data/bot.db`.

## 2. Запуск бота

```bash
python -m app.main
```

### Подготовка скрытой активации

1. На телефоне Сони открой бота и отправь `/start`.
2. Бот ответит `Бот активирован`.
3. Удали у неё и команду, и ответ.
4. Сам факт удаления сообщений не отзывает разрешение бота писать в уже открытый приватный чат.
5. Во время ужина отправь боту со своего аккаунта `/start_quest`.
6. Через `QUEST_START_DELAY_SECONDS` бот запустит этап `meta.intro_step_id`.

По умолчанию задержка — 300 секунд.

```dotenv
QUEST_START_DELAY_SECONDS=300
```

Для мгновенного теста есть `/start_quest_now`.

## 3. Проверка повторных пересылок

Это отдельный технический тест, потому что внешний вид повторно пересланного сообщения зависит от фактического поведения клиента Telegram.

В своём чате с ботом:

```text
/memory_new first_chat
```

После этого по порядку перешли:

- одно старое своё сообщение из диалога с Соней;
- одно её сообщение;
- голосовое;
- кружок;
- фото или стикер.

Затем:

```text
/memory_save
/memory_preview first_chat
```

Бот повторно перешлёт всё тебе. Так сразу видно, сохраняются ли нужные подписи `Forwarded from`.

Для отправки привязанной участнице:

```text
/memory_play first_chat
```

Команды администратора:

```text
/help_admin
/status
/start_quest
/start_quest_now
/cancel_quest
/memory_new <id>
/memory_save
/memory_cancel
/memory_list
/memory_preview <id>
/memory_play <id>
```

## 4. Цветные inline-кнопки

В коде и ROADMAP используются стабильные алиасы:

| Алиас | Telegram style | Назначение |
|---|---|---|
| `default` | без `style` | нейтральная кнопка |
| `primary` | `primary` | синяя, основное действие |
| `success` | `success` | зелёная, подтверждение |
| `danger` | `danger` | красная, риск/отмена |

Алиасы определены в `app/button_styles.py`. Цвет поддерживается актуальным Bot API и свежими клиентами Telegram; старый клиент может показать кнопку нейтрально.

## 5. Проверка прокси отдельным файлом

Скрипт использует тот же `BOT_TOKEN` и тот же `PROXY_URL`, что основной бот.

```bash
python -m tools.proxy_test --chat-id 123456789
```

С маркером:

```bash
python -m tools.proxy_test \
  --chat-id 123456789 \
  --text "проверка VPS Москва"
```

При успехе в указанный чат придёт тестовое сообщение, а терминал выведет `OK`.

Поддерживаются:

```text
http://host:port
socks4://host:port
socks5://host:port
socks5://user:password@host:port
```

## 6. Локальный ROADMAP-конструктор

Никакой сервер и сборка не нужны.

Вариант 1 — открыть двойным кликом:

```text
builder/index.html
```

Вариант 2 — надёжнее через локальный HTTP-сервер:

```bash
python3 -m http.server 8080
```

Затем открыть:

```text
http://127.0.0.1:8080/builder/
```

Конструктор позволяет:

- создавать и перетаскивать этапы;
- добавлять и перетаскивать действия;
- отправлять текст, фото, видео, аудио и документы;
- указывать относительные пути, например `media/photos/clue-01.jpg`;
- задавать HTML, MarkdownV2 или отсутствие парсинга;
- добавлять паузы;
- проигрывать сохранённые воспоминания;
- ждать любой ввод, точный текст, вхождение, regex, число, диапазон или дату;
- задавать последовательные подсказки для неправильных ответов;
- создавать inline-кнопки четырёх стилей;
- задавать переходы между этапами;
- сохранять локальный черновик;
- импортировать и экспортировать `quest.json`;
- проверять ссылки, уникальность ID и обязательные поля.

После экспорта замени:

```text
roadmap/quest.json
```

и проверь файл:

```bash
python -m tools.validate_roadmap roadmap/quest.json
```

## 7. Формат ROADMAP

Упрощённый пример:

```json
{
  "meta": {
    "version": 1,
    "title": "Квест для Сони",
    "entry_step_id": "intro",
    "intro_step_id": "intro"
  },
  "steps": [
    {
      "id": "intro",
      "title": "Интро",
      "notes": "Только для автора",
      "actions": [
        {
          "type": "send_text",
          "text": "<b>Соединение восстановлено.</b>",
          "parse_mode": "HTML",
          "disable_notification": false
        },
        {
          "type": "goto",
          "step_id": "next"
        }
      ]
    }
  ]
}
```

Бот читает JSON напрямую через Pydantic-модели в `app/models.py`. То есть экспорт конструктора одновременно человекочитаемый и исполняемый.

## 8. Медиа

Пути задаются относительно корня репозитория:

```text
media/photos/clue-01.jpg
media/videos/restaurant-intro.mp4
media/audio/voice-01.m4a
```

Приватные файлы лучше держать в `media/private/`: эта папка не попадёт в публичный GitHub. На VPS её нужно скопировать отдельно после клонирования репозитория.
